# WordPress
- Use `$wpdb->prepare()` with `%i` placeholders for table names (SQL identifiers) in `$wpdb->query()` DDL calls instead of raw concatenation with `phpcs:ignore`. Confidence: 0.65
- Fix WPCS errors properly by restructuring code rather than silencing them with `phpcs:ignore` comments. Confidence: 0.82
- Place `phpcs:ignore` comments on the line preceding the suppressed code, not trailing on the same line. Confidence: 0.72
- Use `wp_remote_retrieve_body()` to extract the response body from WordPress HTTP API calls rather than manually accessing the array. Confidence: 0.95
- When an admin notification must persist until the user takes corrective action (e.g., reconnecting a revoked OAuth token), use a persistent site option flag instead of an expiring transient so the notice cannot silently vanish before the admin sees it. Confidence: 0.70
- Return user-facing operation failures (e.g. a rejected install host) as a `WP_Error` with a readable, actionable message — naming the offending host and how to remedy it — instead of a bare plain-string failure, and keep the consuming paths accepting both a `WP_Error` and legacy strings (rendered escaped in admin, forwarded in CLI/REST) so the message always surfaces. The user flagged that a failure must be easy to message back to the admin. Confidence: 0.6
- When replacing legacy admin UI assets (e.g. Dashicons) with the Icons API, render the CORE icon by name (`wp_get_icon( 'core-admin/plugins' )`, `core-admin/brush`, `core-admin/wordpress`, `core/error`, `core/caution`, `core/check`) rather than shipping copies of the legacy artwork or re-drawing it; register a small custom collection only for an icon core genuinely lacks (the core library has `key`/`shield` but no lock), and match core's style (24×24 viewBox, `stroke="currentColor"`, 1.5 stroke-width from the Gutenberg icon set). The user rejected a first implementation that shipped Dashicon-derived SVGs. Confidence: 0.7
- Verify an icon/API's availability against the SPECIFIC target WordPress release, not trunk: trunk may already contain a collection (e.g. `core-admin`) that the release under test does not ship, and WordPress 7.1's icon sanitizer strips `stroke`/`fill` from custom icons. Probe real availability at runtime (e.g. `'' !== wp_get_icon( 'core-admin/plugins' )`) rather than parsing a version number, and fall back to the legacy markup when it is absent. Confidence: 0.65
- Register custom icon collections lazily at the point of use, guarded by the registry (`WP_Icon_Collections_Registry::get_instance()->is_registered( ... )`) — not by hooking `init` and not with a static "already done" flag — so repeated `do_action('init')` in tests cannot trigger duplicate-registration notices and the collection can re-register after a test unregisters it. Confidence: 0.65
- Inline admin icons must adopt core rendering: inherit the surrounding text colour (`currentColor`, so a `color:#f00` wrapper still renders red) and sit on the text line (`vertical-align: middle`) instead of floating above the baseline (`text-bottom`); the user flagged the misaligned icons after the first implementation. Confidence: 0.6
